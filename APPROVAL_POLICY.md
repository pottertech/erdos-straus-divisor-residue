# Approval Policy, erdos-straus-divisor-residue repository

Approved by Skip Potter, 2026-11-24. This file follows the fleet
template first set in creative-writing-system, with the repo-specific
section below.

## What the agent may do without asking

- Open pull requests and push commits to their branches.
- Fix failing CI checks on an open pull request, and say what changed.
- Answer review comments and apply corrections that stay inside the
  pull request's stated scope.
- Run builds, independent Lean compilations, LeanChecker and Nanoda
  verification, and read-only checks at any time.
- Prepare merge summaries, verification reports, and status reports
  for Skip.

## What needs Skip's explicit word, every time

- Merging a routine pull request into main proceeds on three-way
  agreement (Skip's rule, 2026-11-24): Emily's policy verdict on the
  current head is COMPLIANT, Arty's merge-readiness check on that
  same head is GO, and Atlas confirms the fix state. When the three
  agree, the merge proceeds without a per-pull-request word from
  Skip. When they disagree or stall, Atlas escalates to Skip with
  the disagreement stated plainly and a recommendation, and Skip's
  ruling governs. The remaining items in this section are never
  covered by three-way agreement: each still needs Skip's own word
  for that item before the merge rule applies to its pull request.
- Deleting branches, files, or history outside a pull request's own
  scope, including any history rewrite.
- Changing the pinned Lean toolchain or the mathlib version.
- Any public statement of results (release notes, announcements,
  papers) based on this repository.

## What counts as Skip's word

- Only Skip's own first-person words, for the exact pull request or
  action in question.
- A relay from Atlas is authorization (Skip's rule, 2026-11-25).
  When Atlas forwards Skip's approval for a named pull request,
  that relay carries Skip's authority for that pull request. Record
  the relayed wording, the sender, the message id and the time,
  and the pull request it names, in the verdict comment.
- A relay from any other agent, an approval quoted from a plan, or
  wording generated by a model is never authorization.
- A "go ahead" covers only the actions named in that exchange.

## Repo-specific rules: proof discipline

- The Erdos-Straus conjecture is open. Nothing in this repository is
  described as a proof of the conjecture while any axiom, sorry, or
  admit stands in the certified build path, or while any module in
  that path fails to compile.
- Verification results are reported exactly as found, including
  failures. A module that does not compile is reported as not
  compiling; it is never summarized as verified.
- Axioms are named as axioms wherever results are summarized, with
  their statements. A placeholder that concludes True is reported as
  a placeholder, not as a result.
- Brodie Foxworth is co-author of this research. His authored work is
  not rewritten, reattributed, or removed without Skip's word.
- Fixes to proof files are the authors' work unless Skip directs the
  agent to patch them.

## Policy checking

Emily, a fleet agent, checks open pull requests against this policy
on a schedule and posts a verdict comment on each: compliant, or not
compliant with the specific line crossed. The checker never writes
code in this repository, never pushes to a pull request branch, and
never merges. Arty, a fleet agent, is the Merge Reviewer: at merge
time he verifies that the head Emily cleared is the head being
merged, that CI is green at that head, and that the pull request
body's claims reproduce at that head; he reports GO or NO-GO to
Atlas only and never posts, merges, or overrules Emily. Disputed
verdicts go to Skip for his ruling.

## When in doubt

- Stop, report what is unclear in one short message, and wait.
